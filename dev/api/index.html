API

PolycubePuzzles — Module
PolycubePuzzles

Solve packing puzzles: fill a target region of the N-dimensional integer lattice with a given multiset of pieces (polyominoes, polycubes, ...). Puzzles are reduced to exact cover and solved with Knuth's dancing links (Algorithm X), extended with per-piece-type count bounds so identical pieces are never distinguished (no duplicate solutions from permuting copies).

Shapes

PolycubePuzzles.Shape — Type
Shape{N}

A finite set of cells in the N-dimensional integer lattice, stored as a sorted vector of unique NTuple{N,Int} coordinates. Shapes are used both for pieces and for target regions.

Construct with:

  • Shape(cells...) or Shape(cells::AbstractVector) from coordinate tuples,
  • Shape(A::AbstractArray{Bool}) from a boolean array (cells where true),
  • shape"..." / parse_shape from ASCII art,
  • box for rectangular boxes.

Set operations union, intersect and setdiff work on shapes of equal dimension, so a target with holes is e.g. setdiff(box(5,5), Shape((3,3))).

PolycubePuzzles.parse_shape — Function
parse_shape(str)

Parse a shape from ASCII art. . and spaces are empty; any other character is a cell. Columns give the x coordinate (left to right) and lines give y, with the bottom line being y = 1. Blocks of lines separated by blank lines are layers of a 3D shape, the first block being z = 1 (bottom layer first). All layers must have the same number of lines.

Y = shape"""
XXXX
.X..
"""

Puzzles and solutions

PolycubePuzzles.Puzzle — Type
Puzzle(target::Shape{N}, pieces; reflections = false)

A packing puzzle: cover every cell of target exactly once using the given pieces. pieces is a piece => count pair or a vector of them, where count is an Int (use exactly that many) or a UnitRange (use between first and last copies). Copies of one piece type are indistinguishable, so solutions that only permute them are counted once.

reflections controls whether pieces may be mirrored, which is off by default. Turn it on for flat pieces that may be turned over, e.g. pentominoes in a plane. A planar piece in 3D has its mirror image among its rotations anyway.

source

PolycubePuzzles.solve — Function
solve(p::Puzzle; limit = typemax(Int), symmetry = :none, ntasks = Threads.nthreads())

Return up to limit solutions of p as a Vector{Solution}. Without a limit the order is the same as a sequential search, whatever ntasks is.

  • symmetry = :none: with :all, solutions related by a symmetry of the target (rotation or reflection, where these map solutions to solutions) are counted once; with :rotations, only rotations are identified.
  • ntasks: number of concurrent search tasks; start Julia with --threads to run them in parallel.
  • engine = :auto: the search algorithm. :bitboard fills the first empty cell each time, with very cheap steps; :dlx (dancing links) fills the most constrained cell, which can make the search far smaller. :auto estimates both from a few hundred random probes of the search tree and uses the faster.

Assembly

PolycubePuzzles.assembly_order — Function
assembly_order(sol::Solution; up = N, view = nothing, right = nothing)

An order in which to place the pieces of sol when building it by hand, as a permutation of 1:length(sol). Axis up points up (default: the last axis, z in 3D and y in 2D).

Every piece can be slid into place when its turn comes, and the remaining pieces can still be added afterwards, whenever the solution can be built that way at all (see isassemblable and assembly_plan). Within that, at each step the order prefers a piece that rests entirely on the floor, on placed pieces, or on itself, then one that can be dropped straight in over one that must slide in from the side, and then the lowest piece.

If view, a vector pointing from the puzzle towards the viewer, is given, it instead prefers pieces that would be mostly visible from the viewer (not hidden behind placed pieces), and among those the one farthest back, so later pieces go in front, while still filling lower levels before higher ones; right, the viewer's rightward direction, then favours pieces on the left.

PolycubePuzzles.Insertion — Type
Insertion{N}

How a piece gets into place during assembly. kind is :drop (lowered straight down), :slide (pushed straight in along one axis), :path (a sequence of axis-aligned slides) or :blocked (no translation gets it in). moves are the slides as displacement vectors, in order, taking the piece from a position clear of the puzzle to its place.

Plotting

These need a Makie backend, e.g. using CairoMakie.

PolycubePuzzles.plot_solution — Function
plot_solution(sol::Solution; step = length(sol), kw...)

Plot a 2D or 3D solution as a Makie Figure, showing the first step pieces of the assembly order. Requires a Makie backend, e.g. using CairoMakie.

Keywords:

  • step: how many pieces to show. When step < length(sol) the newest piece is highlighted with a heavy outline and the earlier ones are muted.
  • order: the assembly order; by default assembly_order for the plot's viewpoint (in 3D, from the back and left).
  • style: :flat (default; plain colours) or :wood (wood tones with grain running along each piece).
  • colors: the colours (or wood tones) to use; pieces are assigned them by piece_coloring, so touching pieces differ.
  • azimuth, elevation: the 3D viewing angles.
  • muted: mute the earlier pieces when highlighting (default true).
  • ghost: draw placed pieces that hide the newest one as faint ghosts (default true, 3D only).
  • arrows: draw an arrow showing how the newest piece slides in, when it isn't simply dropped (default true).
  • frame: draw the outline of the bounding box (default true).
  • size: the figure size in pixels.

PolycubePuzzles.explore — Function
explore(sol::Solution; style = :flat, kw...)
explore(sols::Vector{<:Solution}; kw...)

An interactive Makie Figure for following the assembly of a solution, or browsing several. Display it with an interactive backend such as GLMakie (using GLMakie; explore(sol)), then drag to turn the view.

  • A slider (or ◀ ▶, or the left and right arrow keys) moves through the steps; the line beside it says what the step does, e.g. "slide in from the left".
  • With several solutions, a second slider (or the up and down arrow keys) chooses the solution.
  • Toggles switch between flat colours and wood, and turn ghosts, slide arrows and muting of earlier pieces on and off; "reset view" restores the angle.

Other keywords are passed to plot_solution!.

source
PolycubePuzzles.instructions — Function
instructions(sol::Solution, filename; title = "Assembly instructions", style = :flat,
             steps_per_page = 6, columns = 2, kw...)

Write printable assembly instructions for sol on A4 pages: a title page with a parts list (each kind of piece drawn on its own, with how many there are) and the finished puzzle, then the steps, steps_per_page to a page in columns columns, each numbered, with a note when a piece must slide in from the side.

If filename ends in .pdf the pages go into one PDF, which needs using CairoMakie; otherwise each page is saved as its own image, e.g. booklet.png gives booklet_1.png, booklet_2.png, .... Returns the file name(s). Other keywords are as for plot_solution.
